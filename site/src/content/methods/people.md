# People and bots

A person is an account that GitHub does not type as a bot and that [`data/bots.yaml`](https://github.com/jhoblitt/rook-dev-stats/blob/main/data/bots.yaml) does not list. This site identifies people by their GitHub login, and a pull request opened by an account since deleted, which has none, by the name on its commits ([Deleted accounts](#people-deleted-accounts)). Its published data keeps no profile and no name but that one, and is built to keep no e-mail address, though text a contributor wrote, such as a pull request's title, can name someone or hold an address: see [What the data keeps about a person](#privacy).

## Bots

GitHub types some accounts as bots itself, such as the accounts of GitHub apps: Mergify, which opens most of rook/rook's backports, and Dependabot, which opens its dependency updates, are among them. Other accounts are automated but typed as people's accounts, such as `jenkins-rook`, rook/rook's Jenkins CI; `data/bots.yaml` lists those, each with the reason, and matches a login in any case. A bot's comments and reviews are counted apart, as bot comments and bot reviews. They are never a response, a human review, or a reviewer's.

## The pull request's author

What the author of a pull request does on it is counted apart from what others do: a comment by the author is not a response, and a review by the author, such as a reply in a review thread, is not a review. Both are kept in the data as events of their own kind.

## Deleted accounts

GitHub gives no account for what a deleted account did and shows it as the placeholder user `ghost`. Every deleted account shares it, so nothing GitHub gives about an account tells one deleted account from another.

A pull request opened by an account since deleted is credited instead to a name on its commits. Git records two names on each commit, its author's and its committer's, and the pull request is credited to the committer name carried by the most of its commits, leaving out the commits whose committer is "GitHub", the name GitHub records on a commit it makes itself through its website, such as a suggestion applied or the base branch merged in. Only when every commit's committer is "GitHub" is the pull request credited to the author name carried by the most of its commits instead: a backport's commits keep the authors of the commits it copies, so an author's name can be another person's. When any other committer is there, the authors are never used, even when that committer's name was dropped as below or is empty, and when no such committer gives a usable name, the pull request has none. On a tie, the name found on the earliest commit, in the order GitHub lists them, wins. The page shows the name as "(deleted)" followed by it, with no link.

For these pull requests only, the site's fetch asks GitHub for the author's and the committer's name of each commit, and in that request for no e-mail address. Git's name is free text, so before a name is kept its control and format characters are removed and each run of white space becomes one space, and a name that holds an `@`, which may be an address, is dropped whole: it is not kept among the names, is never a candidate and is never published. The names left are kept in the fetch's local cache, which is not published; the published records keep only the name the pull request is credited to. The cache also keeps every commit's message as GitHub gives it, for every pull request, and a message's `Signed-off-by:` line usually carries a name with an address; the cache is not published, and the records keep no line written as a `Signed-off-by:` trailer ([What is withheld](#privacy-what-is-withheld)). Names are compared as they are left by this cleaning. It is a name, not an account, so two people with the same name are one person here, and one person whose name is written two ways, even in a different case, is two. A commit's committer is whoever last committed it, by committing, rebasing or cherry-picking it, who need not be who wrote it: so such a pull request is credited to whoever committed the most of its commits, and when another person committed them, that is someone other than the deleted account that opened it. The name can be that of someone whose account still exists, such as whoever committed a backport: "(deleted)" describes the account that opened the pull request, not the person named. GitHub no longer shows these pull requests under any name; this site does, from what git keeps.

Comments and reviews by a deleted account carry no name and cannot be told apart, so they are all credited to one entry, shown as "(deleted, unknown)", as is a pull request opened by a deleted account whose commits give it no name by the rule above. A comment by a deleted account on a pull request opened by a deleted account counts as one by another person, even when the pull request is credited to a name: the two are not known to be the same.
